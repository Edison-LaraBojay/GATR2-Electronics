## Interface notes for other workers (W2 viewer, W3 capture, W0 perf)
- **Contracts.** hello, state, diag and frame say `navigatr.inspect/2`. `GET /api/snapshot` keeps `contract:"navigatr.inspect/1"` and the full shape, with `trail`.
- **Every message** has `type`; `seq` counts per channel. `host_ms`/`host_us` are Pi HostClock at build time.
- **hello** adds:
  - `client_id`: the id in `diag.inspection.clients[].id`;
  - `features {state_hz, max_state_hz, diag_hz, capture, instrumentation, telemetry, history_max, attitude_fresh_ms}`;
  - `inspection` gains `state_hz` and `diag_hz`.
- **capture** is FLAT: `{"type":"capture","seq":n,"host_ms":t, ...writeStatus fields}`.
- **instrumentation** is FLAT: `{"type":"instrumentation","seq":n,"host_ms":t, ...writeInstrumentation fields}`.
- **event**: `{"type":"event","seq":<RuntimeEvent.sequence>,"host_ms":t|null,"text":...}`. `seq` equals `diag.events[].sequence`; dedupe by it.
- **telemetry**: `{type, seq, host_ms, received_host_ms, age_ms, session, stamp_ms, flags, attitude|null, motion|null, wheels|null}`.
  - motion carries `state/state_name`, `reason/reason_name`, `mode/mode_name` and `drive_fault/drive_fault_name`.
- **robot.attitude.status** is `measured`, `stale`, `assumed_level` or `unavailable`. It sits after `assumed_level`.
- **Preview binary header** has `detection`: the detection_frames entry of exactly that frame.
- **Session reset:** unsent replaceable messages are cleared, then hello, then history. A state or diag carrying the new session can arrive just before that hello; clients adopt the session from any message (the viewer does; docs changed in the FIX). No message labels older data with a newer session.
- **HttpResponse** has `shared_body`: a large body sent without a copy.
- **HTTP methods.**
  - GET and POST reach the handler; POST works only on the capture routes, and elsewhere gets 405 `Allow: GET`.
  - Other methods get 405 `Allow: GET, POST`.
  - A POST body is read up to 64 KiB (413 above).
- **`max_clients` now counts WebSocket feed clients only.** Plain HTTP connections have their own cap of 32. This fixed the viewer's module loads getting 503.
- **New `<Inspection>` attributes:**
  - `state_hz` (30, (0, 60]);
  - `diag_hz` (4, (0, 20]);
  - `reliable_kb` (256, at least 128 since the FIX);
  - `send_buffer_kb` (16 since the FIX, 0 = the OS default; feed sockets only);
  - `ack_window_kb` (64, 0 = flow control off; added in the FIX).

  `snapshot_hz` still parses and is not used.
- **For W0:**
  - queue stats: `diag.inspection.clients[].channels.<name>.{queued,sent,replaced,refused,dropped,bytes,last_latency_ms}`;
  - build costs: `diag.inspection.build.{state,diag,history,instrumentation}.{count,last_us,mean_us,recent_mean_us,max_us,last_bytes,mean_bytes}`.

## FIX (2026-09-28): review findings on W1's work, DONE
Stage result: `stage_results/W1_fix.md`. Host validation only (Windows 11, MinGW GCC 15.2, Debug, loopback); nothing on the Pi or robot.

**Per finding**
1. (medium) Latest-wins bypassed by kernel buffering: FIXED.
   - WebSocket ping/pong flow control in `http_server.cpp`: a ping after each frame carries the byte position; once a client answers the probe ping, at most `ack_window_kb` (64) unconfirmed, a replaceable frame starts only with <= 16 KiB unconfirmed and at most 2 per channel unconfirmed, large replaceable frames (>= 4 KiB: diag, previews) one at a time with a gap of 3x the last one's delivery time (max 4 s). Works through SSH tunnels and proxies, which kernel knobs cannot bound.
   - The lead's 12.2 items: `send_buffer_kb` default 16 (feed sockets only; HTTP downloads keep the OS default) and `TCP_NOTSENT_LOWAT` on Linux (untested on host: Windows has no such option). Clients that never answer pings get only these, with large frames paced by write completion.
   - Tests at the default config with no grace period: `RateLimitedReaderGetsFreshStatesAtTheDefaults`, `PausedClientResumesWithFreshStatesNotABacklog`, `FlowControlKeepsOldStatesOutOfTheNetwork` (also covers a client that does not answer pings).
2. (low) reliable_kb floor below hello/history size: FIXED. A reliable message is admitted when the FIFO is empty whatever its size; floor raised to 128 (`kMinReliableKb`). Tests: `ReliableBudgetBoundsTheBacklogNotOneMessage`, `MinimumReliableBudgetOpensEveryClientWithAFullTrail`; config test rejects 127.
3. (low) Identical-diag skip never fired while running: FIXED. `JsonWriter::recordVarying` marks varying values (every time, age, stamp, cycle, the robot block, counters, sequences, worker timing, run/traffic counts, hub posted/queued/drained, dropped_intervals, stillness progress); the hash skips them. Unchanged content refreshes at 1 s (was 2 s keepalive). Tests: `UnchangedDiagIsSkippedWhileTheWorkersRun`, `DiagHashIgnoresTheMovingRobotButNotContent`, doc test `DiagHashIgnoresVaryingValuesButNotContent`.
4. (low) Reset label read after the snapshot: FIXED. `underOneReset` reads resetCount before the data and checks after, rebuilding (3 attempts); state and diag are skipped for the tick when unstable. docs now say clients adopt the session from any message (what the viewer does). Test: `ResetsUnderLoadNeverLabelAnOldPoseWithTheNewSession` (resets every 25 ms under load; a guard, it cannot reliably reproduce the few-instruction window).
- Found while fixing: a client answering pings could send a pong after its close; an immediate closesocket then reset the connection and the close echo could be lost (seen once in 4 suite repeats). Fixed with a lingering close (shutdown send, wait for EOF, 1 s bound).
