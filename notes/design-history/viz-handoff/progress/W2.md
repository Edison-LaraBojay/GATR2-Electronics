## Key behaviour (for reviewers)
- Handlers parse and store only; one rAF loop applies the newest state/diag/telemetry to the scene; DOM panels at
  <= 10 Hz, visible only; the instrumentation tab subscribes only while visible (raw/decoded only on request).
- Graph samples, trail points and latency statistics are taken per message in the store hook (bounded typed arrays),
  so latest-wins slots never lose samples when frames are slow.
- Smoothing: interpolation over one state period (<= 100 ms), snap on identity/validity/placement/reconnect,
  jumps > 0.2 m or > 15 deg, and when stale (no state 250 ms, or pose age > 250 ms). Toggle "smooth".
- Render budget: frames costing > 12 ms are spaced so drawing takes about a third of the main thread
  (full rate while dragging). `?nobudget` disables it for measurement.
- Replay: REPLAY banner, live-only controls disabled (preview budget, capture start/cancel), live side panels tagged
  LIVE and dimmed, nothing sent except pings/subscriptions.
- Load retry: index.html awaits import('./app.js') and reloads (<= 5 times) if a module fetch failed (see issue 6).

4. Slow link staleness (measured, Windows loopback, pacing proxy, synthetic demo, 2026-09-28):
   - 400 KB/s: p50 110-140 ms. 40 KB/s, send_buffer_kb=8: diag on 1.5 s, diag off 112 ms.
     40 KB/s, OS default send buffer: 3.6 s (2.3 s with diag off). No run showed unbounded growth.
   - diag messages are ~20 KB each (4 Hz = 80 KB/s); an in-flight diag delays the next state by its transmission time,
     and the OS send buffer holds seconds of stale bytes at low rates. Suggest a small default send_buffer_kb (8-16)
     and/or TCP_NOTSENT_LOWAT on Linux for WebSocket sockets, and a leaner or rate-adapted diag for slow clients.
5. Viewer sends only: ping, subscribe, history (after an odometry epoch change, on tab re-show, after leaving replay),
   preview. Nothing else.
6. (resolved by W1) max_clients counted every TCP connection, so a slow page load could get 503 for a module.
   W1 now counts feed clients only; the viewer's reload-on-failed-module stays as defense in depth.
7. W5 target validity: the viewer draws the telemetry destination only while running/settling, or with flag bit 3.
