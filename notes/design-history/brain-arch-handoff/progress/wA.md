### Client behavior (decisions beyond the spec text)
- Priority: HELLO, placement, control, profile sync, due state poll, READ_WHEELS, map chunk,
  estimate chunk, path report. Reads and transfers go while the poll is not due; a waiting
  transfer also goes after 4 due polls in a row (starvation guard, CONTRACT ISSUES 1).
- Timeout per request: `response_timeout + byte_time * max(0, req_frame + max_reply_frame - 85)`,
  max reply from `brainReplyMaxLen(op, kResultOk)`. `Client::responseTimeout(op, len)` is public.
- SET_POSE and CONTROL are the only requests resent with the same bytes (plus HELLO). After a
  timeout they are resent before any other request (finding B; for CONTROL it matters because a
  waiting placement outranks it). After Pending: SET_POSE is resent after pending_retry, with one
  state poll first when bench_imu is set; CONTROL is asked again every control_retry (0.1 s)
  until it settles or control_wait (20 s) passes. Everything else (state, profile write/apply,
  READ_DOC, READ_WHEELS, PATH_REPORT) uses a new request id each time (idempotent by content).
- Profile: decode + validateRobotProfile at construction; a failure is `ProfileSync::kInvalid`
  with reason/detail and nothing is sent. Sync starts at the first state of a session: state
  shows mine applied -> kApplied with no upload (idempotent Brain restart); otherwise write from
  offset 0, continue at the Pi's `received`, APPLY; Pending -> APPLY again every pending_retry;
  Ok or state applied -> kApplied; ProfileRejected -> kRejected, settled with the Pi's
  reason/detail until the session changes or resubmitProfile(); InvalidArgument (staging lost or
  replaced) -> rewrite from 0, and 3 in a row -> kRejected with result InvalidArgument. A profile
  op timeout delays the next profile request by one state_period so a state poll goes between.
- Placement is refused (ticket 0) unless ready and (no profile configured or kApplied).
- Map: read by the state's map_id (never doc_id 0). DocAssembly checks kind, doc_id, offset,
  total_len and crc; a complete document needs crc32 == map_id and validateFieldMap. The cache is
  keyed by map_id and kept across sessions and Pi restarts (not across Brain boots). Stale or
  invalid 3 times in a row -> transfer_backoff (1 s). Unavailable -> field_period.
- Estimate: read by the state's estimate_id while the map is current, at most one start per
  field_period (0.5 s); checked with validateFieldEstimate against the cached map and its header
  id. Stale -> restart at once from the newest id; 3 failures in a row -> transfer_backoff. It is
  published with the map as one generation (`FieldPublication`); partial documents are never
  visible. Session loss clears assemblies and keeps the published pair.
- Estimate ages: the client records, per estimate id, the send time of the last state poll whose
  reply did not show it (`snapshot_after`). LinkDriver sets the observed age at received_at to
  age_ms + (completed_at - snapshot_after), an upper bound. An id already current at the first
  state of a session has an unknown snapshot time: its observed age is +infinity, so resolve()
  reports kStale for any max_age. See CONTRACT ISSUES 2.
- Control: `control(action)` is public, plus recalibrate/reinitialize/reinitImu/
  restartAcquisition. Results kOk, kFailed (detail), kNotStationary, kNotReady, kRejected,
  kTimedOut, kSessionLost; one at a time; refused without a session.
- READ_WHEELS: `requestWheels()` (one attempt) and `wheelReadings()` (sequence, received_at,
  round_trip, result, count, gatr2::WheelReading[4]).
- Path report: latest wins, one attempt, dropped without a session; more than 13 points are
  thinned evenly (rounded), keeping first and last; mode > 2 refused.
- LinkDriver status order: kNoLink, kNoProfile, kCalibrating (Running, WaitingStill,
  WaitingData), kUnplaced (not localized, anchor not accepted, or a placement pending), kNoPose,
  kValid. Frame numbers come from a 4-entry identity table shared by robot() and field(), so
  equal (pi_instance, session, epoch, anchor) give equal numbers: field.frame == robot.frame
  exactly when the estimate is under the robot's anchor. PathSink sends translate end points
  (deduplicated), mode from Path::mode; an empty path clears; a non-finite path is dropped.

### PROSLINK API
```
#include "communigatr/pros_link.h"      // PROS only
enum class Transport { kUsb, kSmartPort };           const char* toString(Transport);
struct LinkConfig {
  Transport transport = kUsb; uint8_t smart_port = 0; int32_t baud = 115200;
  uint32_t poll_period_ms = 2; uint32_t task_priority = TASK_PRIORITY_DEFAULT + 1;
  uint32_t call_timeout_ms = 20;                     // bounded wait of every public call
  std::optional<RobotProfile> profile;               // set: replaces client.profile
  ClientConfig client;                               // bench_imu runs in the poll task, under the mutex
  LinkDriverConfig driver;                           // accept_configured_anchor
};
class ProsLink : investigatr::StateSource, investigatr::PathSink {
  explicit ProsLink(const LinkConfig&);             // keep for the program's life
  bool start();                                      // creates the poll task; retry while false
  static Seconds now();                              // micros * 1e-6, pass to robot() and controllers
  ProsLinkStatus status() const;
```
